# Internationalisation : conception

*Note de conception, 19/10/2026 (audit 6, Id1), mise à jour le 20/10/2026 avec les fondations (lot 1). L'application devient multilingue dans les cinq langues du site : français (référence), anglais, allemand, espagnol et chinois simplifié. Les fondations sont en place (réglage, `t()`, formateurs, `internal/msg`, locale des formules) ; l'extraction des textes et les traductions suivent par lots.*

## 0. Règle pour le code nouveau

- **Tout texte nouveau de l'interface passe par `t()`** (`#lib/i18n/index.js`), avec sa clé dans `frontend/src/lib/i18n/messages/fr/<espace>.json` ; jamais de texte en dur dans le balisage, un `title`, un `aria-label` ou un module `.ts`.
- **Tout nombre ou date affiché passe par les formateurs** (`fmtNumber`, `fmtInteger`, `fmtPercent`, `fmtDate`, `fmtTime`, `fmtDateTime`, `numberFormat`, `compareText`, `lower`) ; plus jamais `'fr-FR'` ni `'fr'` en dur.
- **Toute erreur Go nouvelle montrée à l'utilisateur est un `*msg.Error`** (`msg.New(id, msg.Args{…})` ou `msg.Wrap(sentinelle, id, …)`), avec son texte dans `internal/msg/fr.go` ; pas de `fmt.Errorf` en français pour un message qui atteint l'interface.
- Une erreur du moteur s'affiche par `errorText(e)` (pas `e instanceof Error ? e.message : String(e)`), pour prendre son texte traduit.

## 1. État des lieux

| Couche | Aujourd'hui | Prêt pour une autre langue ? |
|---|---|---|
| Réglage | `ui.language` : `auto` (système sur le bureau, navigateur en web ; l'anglais si la langue n'est pas proposée), `fr`, `en`, `de`, `es`, `zh` ; Fichier › Paramètres › Affichage, chaque langue écrite dans sa langue ; imposable par la stratégie. | Oui. |
| Interface Svelte | Module `frontend/src/lib/i18n/` : `t()`, catalogues par espace de noms, formateurs `Intl`. Les ~95 `'fr-FR'` / `'fr'` en dur passent par les formateurs. Les textes, eux, sont encore en dur dans ~60 composants et les modules `.ts`. | Les nombres et les dates oui ; les textes à extraire (lot 2). |
| Messages du moteur Go | Paquet `internal/msg` : catalogue par langue, `*msg.Error` traduits par le pont. Dix messages convertis en exemple ; le reste est en `fmt.Errorf` français, et `internal/sqltext`, `driverfr.go` traduisent toujours vers le français. | Le mécanisme oui ; les messages à convertir (lot 3). |
| Formules | Le moteur connaît les noms FR et EN de chaque fonction ; `formula.Locale` sépare langue des noms et séparateurs, `formula.ForLanguage` choisit la locale d'une langue. Les formules des colonnes sont stockées en anglais. La session porte sa locale (`canvas.Model.SetLocale`) ; elle règle déjà la lecture des nombres écrits en texte (`Schema.Numbers`, décision 0013). | Saisie et affichage encore à la française (§ 5). |
| Aide intégrée | Pages Markdown (`frontend/src/lib/help/pages/*.md`). | À dupliquer par langue : facile, ce sont des fichiers. |
| Assistant IA, scripts Lua, API MCP | Consignes et descriptions d'outils en français ; noms de commandes en anglais (`tables.read`). | Les noms d'API restent en anglais ; les descriptions suivront le catalogue Go. |

## 2. Principes

1. **Une clé par message, le texte français comme valeur de référence.** Les clés décrivent l'endroit et le sens (`ribbon.home.paste`, `grid.sort.asc`), pas le texte.
2. **Des paramètres nommés, jamais de concaténation** : `« {name} » existe déjà`, pour que l'ordre des mots puisse changer d'une langue à l'autre. Pluriels par une forme ICU minimale (`{n, plural, =0 {aucune ligne} one {# ligne} other {# lignes}}`).
3. **Le format du fichier ne dépend jamais de la langue** : formules en anglais, nombres et dates en valeurs brutes, noms de tableaux et de colonnes tels que l'utilisateur les a tapés.
4. **La langue suit le système**, sauf choix explicite dans Fichier › Paramètres ou dans la configuration d'entreprise (`ui.language`).
5. **Le moteur Go renvoie des erreurs typées** (identifiant et paramètres) quand l'interface doit les afficher ; le texte se construit au bord (pont ou transport web), dans la langue de la session.

## 3. Côté interface (Svelte)

### Le module `frontend/src/lib/i18n/`

| Fichier | Rôle |
|---|---|
| `index.ts` | Point d'entrée : `import { t, fmtNumber } from '#lib/i18n/index.js'`. |
| `core.ts` | Logique pure : langues (`LANGS`, `LANG_NAMES`, `LOCALES`), `resolveLang`, mise à plat des catalogues, rendu des paramètres et pluriels (`render`), forme d'un message (`shape`). |
| `i18n.svelte.ts` | État (langue courante, rune Svelte), `t()`, `tAny()`, `setLang()`, formateurs. |
| `errors.ts` | `errorText(e)` : texte d'une erreur, traduit si le moteur l'a envoyé avec sa cause. |
| `messages/<langue>/<espace>.json` | Catalogues : un fichier par espace de noms et par langue, objets imbriqués. Le français est embarqué ; les autres langues sont chargées à la demande (`import.meta.glob`, un petit fichier par espace). |
| `keys.d.ts` | Généré par `npm run i18n:types` (lancé aussi par `npm run check`) : chaque clé française et ses paramètres. `svelte-check` refuse une clé inconnue ou un paramètre manquant. |
| `i18n.test.ts` | `t()`, pluriels, repli, formateurs par langue, et cohérence des catalogues : les autres langues ont les mêmes fichiers que le français, seulement des clés françaises, avec les mêmes paramètres et pluriels ; `keys.d.ts` est à jour. |

### `t()`

```ts
t('common.cancel')                       // « Annuler »
t('common.rows', { n: 3 })               // « 3 lignes » ; { n: 0 } → « aucune ligne »
t('shell.settings.language.auto', { name: 'English' })
tAny(`grid.type.${type}`)                // clé calculée : sans vérification de type
```

- Clé = espace de noms (nom du fichier) + chemin dans le JSON : `messages/fr/shell.json` › `settings.language.label` → `shell.settings.language.label`.
- Syntaxe (la même que `internal/msg`) : `{nom}` remplacé par le paramètre (un nombre est écrit dans la langue) ; `{n, plural, =0 {…} one {# …} other {# …}}` choisit d'abord `=N`, puis la catégorie CLDR de la langue (`Intl.PluralRules` : en français 0 et 1,5 sont au singulier), puis `other` ; `#` est le nombre. Pas d'échappement par apostrophe : « l'onglet » s'écrit tel quel.
- Une clé sans texte dans la langue courante rend le texte français (avertissement en développement, une fois par clé) ; une clé absente partout rend la clé elle-même (erreur en développement).
- Réactivité : `t()` et les formateurs lisent la langue, un état Svelte. Un composant qui les appelle dans son balisage ou dans un `$derived` se redessine quand elle change. Un texte calculé une fois au chargement d'un module (constante de module) ne change pas : le calculer dans une fonction ou un getter (voir `ui.language` dans `shell/settings.ts`).

### Formateurs

`fmtNumber(n, opts?)`, `fmtInteger(n)`, `fmtPercent(n, opts?)`, `fmtDate(d, opts?)`, `fmtTime(d, opts?)`, `fmtDateTime(d, opts?)`, `numberFormat(opts?)` et `dateTimeFormat(opts?)` (objets `Intl` gardés par langue et options), `compareText(a, b, opts?)` (tri), `lower(s)`, `upper(s)`, `decimalSep()`. Locales : `fr-FR`, `en-US`, `de-DE`, `es-ES`, `zh-CN`.

**Valeurs des cellules** : leur affichage suit la langue de l'interface, comme Excel suit celle du système (nombres, pourcentages, monétaire, noms des mois et des jours des formats de date) ; la valeur stockée ne change pas. Restent à la française jusqu'au lot 6, parce que la saisie l'est encore : les dates d'une colonne Date (jj/mm/aaaa), VRAI/FAUX, et les textes que le moteur met déjà en forme (valeurs des cellules libres, résultats de formules rendus en texte).

### Langue de la session

`loadSettings()` (`shell/settings.svelte.ts`) résout la langue au démarrage et après chaque changement du réglage : `ui.language` s'il nomme une langue ; `auto` : la langue du système que donne le moteur sur le bureau (`Platform().locale`, Windows : langue d'affichage préférée, ailleurs `LC_ALL`, `LC_MESSAGES`, `LANG`), sinon celle du navigateur (`navigator.languages`) ; une langue non proposée donne l'anglais. Puis `setLang()` charge ses textes et met à jour `<html lang>`, et `DocumentService.SetLanguage` la donne au moteur. Le changement s'applique **sans redémarrer** pour tout ce qui passe par `t()` et les formateurs.

Les tests restent en français : la langue vaut `fr` tant que `setLang` n'est pas appelé.

### Conventions pour l'extraction (lot 2)

- **Espaces de noms** (un fichier par espace, pour extraire en parallèle sans conflit) : `common` (mots partagés : OK, Annuler, Fermer, pluriels « n lignes »…), `shell` (barre de titre, menus Fichier, paramètres, onglets des feuilles, barre d'état, boîtes générales), `ribbon` (onglets, groupes et commandes du ruban, info-bulles, raccourcis), `grid` (feuille, tableaux, colonnes, filtres, tris, mise en forme, TCD), `remote` (classeurs partagés, serveur Lattis, Data Lake, droits, formulaires), `query` (requêtes d'import, Power Query), `sql` (onglet SQL), `script` (onglet Script, Lua, boutons), `chart` (graphiques, cartes), `doc` (onglets document, pages web), `ai` (assistant IA, MCP), `help` (aide intégrée, référence), `errors` (messages d'erreur construits par l'interface). Un espace nouveau : un fichier dans **chacune** des cinq langues (le test le vérifie).
- **Clés** : en anglais, en `camelCase`, du général au particulier, d'après l'endroit et le sens : `ribbon.home.paste`, `ribbon.home.paste.tooltip`, `grid.filter.clear`, `shell.settings.language.label`, `remote.share.dialog.title`. Suffixes usuels : `.label`, `.title` (titre de boîte), `.tooltip` (attribut `title`), `.aria` (`aria-label`), `.help`, `.placeholder`, `.confirm`. Une même phrase à deux endroits a deux clés si le sens ou le contexte diffère ; les mots vraiment communs vont dans `common`.
- **Textes** : copiés tels quels (espaces insécables, guillemets « », apostrophes typographiques compris), avec les mots du glossaire (`docs/glossaire.md`). Paramètres nommés en anglais (`{name}`, `{table}`, `{n}`), jamais de concaténation de morceaux de phrase ; un pluriel « ligne(s) » ou `n > 1 ? 's' : ''` devient `{n, plural, one {# ligne} other {# lignes}}`.
- **Ne pas traduire** : noms tapés par l'utilisateur, noms de fonctions de formule (ils viennent du moteur), noms de commandes de l'API Lua/MCP, raccourcis clavier (`Ctrl+Z`), noms de produits.
- Après avoir ajouté des clés : `npm run i18n:types` (ou `npm run check`), et ne remplir que `messages/fr` ; les autres langues sont l'affaire des traductions (un fichier de langue ne contient que des clés françaises, avec les mêmes paramètres).
- Les modules purs (`grid/a11y.ts`, `shell/settings.ts`, `shell/shortcuts.ts`, ruban) passent les premiers ; pour une constante de module, un getter ou une fonction (voir § 3, réactivité). Les tests qui vérifient un texte français restent valables : la langue des tests est le français.
- Remplacer en passant `e instanceof Error ? e.message : String(e)` par `errorText(e)`, et les tests sur le texte d'une erreur du moteur (`/existe déjà/` dans `ui/names.ts`) par son identifiant (`msgCause(e)?.id`).
- `Sheet.svelte` et `+page.svelte` : suivre le découpage de `docs/decoupage-sheet.md` pour ne pas doubler les conflits.

## 4. Côté moteur (Go)

- **`internal/msg`** : `Lang` (`fr`, `en`, `de`, `es`, `zh`), `Parse`, `Resolve(réglage, système)`, `SystemLocale()` ; catalogue `map[ID]string` par langue (`fr.go`, la référence, et `en.go` complets ; `de`, `es`, `zh` vides pour l'instant), `Format(lang, id, args)` avec la même syntaxe que `t()` (pluriels CLDR simplifiés) ; une clé absente rend le français, puis l'identifiant.
- **`*msg.Error{ID, Args, Err}`** implémente `error` : `Error()` est le texte français (journaux et tests lisibles, `erreurs.log` reste en français), `Text(lang)` la traduction, `Unwrap` rend la sentinelle (`errors.Is(err, canvas.ErrTable)` reste vrai), deux `*msg.Error` de même identifiant sont `errors.Is`. `msg.Text(lang, err)` traduit aussi une erreur qui en enveloppe une (`fmt.Errorf("import : %w", e)` : seul le texte de `e` change).
- **Identifiants** : pointés par domaine, en anglais (`doc.none`, `table.nameTaken`, `sheet.nameTaken`, `script.timeout`, `config.locked`) ; paramètres nommés comme côté interface.
- **Pont** : la langue de la session vient de l'interface (`DocumentService.SetLanguage`) ; avant, le réglage et la langue du système. Sur le bureau, `bridge.MarshalError` (option `MarshalError` de Wails) ajoute à l'erreur d'appel une cause `{id, args, message}` dans la langue de la session ; le texte de l'erreur reste le français et `errorText` prend `cause.message`. En web, le transport (`transport.Hub.Translate`, branché par le moteur sur `bridge.ErrorTranslator`) envoie directement le texte traduit, avec la même cause. Une erreur ordinaire garde son texte, comme avant.
- **Erreurs typées** : une erreur qui porte ses propres champs (`canvas.ErrKey`, les erreurs de `internal/archive`, de `internal/sqltext`…) implémente `msg.Messager` (`error` + `Msg() msg.Message`), son `Error()` valant `Msg().String()` ; `msg.Text` et le pont la traduisent comme un `*msg.Error`.
- **Messages qui ne sont pas des erreurs** (notes de la barre d'état, raisons, morceaux d'un autre message) : `msg.M(id, args)` donne un `msg.Message` ; `String()` est le français, `Text(lang)` la traduction. Un paramètre qui est lui-même un `Message`, un `*msg.Error` ou un `Messager` s'écrit dans la langue du message qui le contient ; `Args.In(lang)` rend les paramètres prêts pour JSON (la cause envoyée à l'interface).
- **Langue de la session dans le moteur** : `canvas.Model.SetLanguage` (posée par le pont avec la locale des formules, `applyLocale`) et `Model.Language()` ; les notes que le moteur écrit lui-même passent par un petit `say(id, args)` (`Model`, `tx`, `bridge.DocumentService`, moteurs de `collab` et `coedit`, page de connexion de `auth`), qui rend le texte dans la langue de la session. Les fonctions qui rendent une note hors de ces objets ont une variante `…In(lang)` à côté de la version française : `collab.UndoNoticeIn`, `doc.Document.TakeOpenNoticeIn`, `workbook.InspectIn`, `bridge.PushSummaryIn`.
- **SQLite et pilotes** : `internal/sqltext` et `internal/query/driverfr.go` sont des tables de correspondance du texte d'origine vers un identifiant (`sql.sqlite.*`, `connection.driver.*`), le texte d'origine restant en paramètre (`{detail}`) pour le support ; un message SQLite inconnu passe tel quel (`sql.raw`).
- Les identifiants écrits en toutes lettres dans le code (`msg.New`, `msg.Wrap`, `msg.M`, `msg.Format`, `say`) doivent exister dans `fr.go` (`TestIDsInCatalogue`) ; chaque catalogue traduit non vide a exactement les identifiants du français, avec les mêmes paramètres et pluriels (`TestCatalogueParity`).
- Restent en français : les journaux (`erreurs.log`), le texte `Error()` des erreurs, et les rares textes construits hors catalogue (libellés de suivi d'un onglet à choix, `canvas.FollowLabel`). Les descriptions des commandes de l'API (`internal/api`) n'ont pas encore de texte par langue ; leurs noms ne changeront pas.

## 5. Formules

- `formula.Locale` est une structure : `Names` (langue des noms de fonctions et de VRAI/FAUX : `NamesFR`, `NamesEN`, `NamesDE`, `NamesES`) et `Dot` (décimale « . » et arguments séparés par « , » ; sinon « , » et « ; »). La valeur zéro est le français ; `formula.FR` et `formula.EN` gardent leur sens.
- `formula.ForLanguage(lang)` : `fr` → noms français, `;` ; `en`, `zh` → noms anglais, `,` ; `de`, `es` → noms anglais (en attendant les leurs, lot 5 : il suffira d'une colonne de noms et d'un cas dans `funcDef.name`), `;` et décimale `,`. Les colonnes calculées restent stockées en anglais (`formula.EN`) : changer de langue ne touche pas au fichier.
- La session porte sa locale : `canvas.Model.SetLocale`, posée par le pont à l'ouverture d'un classeur et à chaque `SetLanguage`. Elle sert dès maintenant à `Schema.Numbers` (lecture des nombres écrits en texte, décision 0013).
- **Reste à faire (lots 5 et 6)** : la saisie et l'affichage des formules utilisent encore `formula.FR` en dur dans `canvas` (`prepareFormula`, `displayFormula`, règles, noms, légendes, `FormulaHelp`). Piège : le texte brut des **cellules libres** (`_lattis_cells.raw`, formules comprises) est stocké **en français** ; passer la saisie à une autre locale demande de convertir à l'entrée (locale → stockage) et à l'affichage (stockage → locale), sinon un classeur saisi en anglais serait mal relu. De même pour les valeurs tapées (dates jj/mm/aaaa, décimale) que lit le moteur.

## 7. Points de vigilance

- **Les noms tapés par l'utilisateur ne se traduisent pas** (tableaux, colonnes, feuilles), ni les noms par défaut déjà enregistrés (`Tableau1`, `Feuille1`, `TCD1`). Un nouveau nom par défaut prend la langue de la session.
- **Les scripts Lua et les pages web d'un classeur** voient les textes que l'application leur renvoie : les messages d'erreur de l'API changeraient de langue d'un poste à l'autre. Un script ne doit donc tester que les codes d'erreur, ce qu'il faudra documenter.
- **L'assistant IA** reçoit ses consignes en français ; il peut répondre dans la langue de l'utilisateur sans changer les consignes.
- **Accessibilité** : l'attribut `lang` de la page suit la langue de l'interface, pour que les lecteurs d'écran choisissent la bonne voix.
- **Code qui lit un message français** (`ui/names.ts` cherche « existe déjà ») : à passer aux identifiants (`msgCause(e)?.id`) avant les traductions.
